The 2017 set in the other log is webOS 3.9, and DejaVuln still applied there. This C1 is webOS 6 on software 03.53.45. The same number is past every older public method.

SlopBroopen on this build CanI.RootMy.TV lists 03.53.45 as the last vulnerable build. European C1 sets on this software and webOS version were already confirmed, through 26 Oct 2026.

A failed software root is described by Homebrew as leaving the set as it was. The brick cases are later changes: writing the kernel or rootfs, and marking files immutable. No C1 report found in this pass was a permanent brick from a failed root attempt. A wrong Homebrew build on a C1 at 03.33.11 left SSH dead for about a day, then recovered. A US 77-inch G1 on this same firmware launched SlopBro’s apps and never fetched the page. That report did not describe a brick.

The G1 and this C1 share HE_DTV_W21O_AFABATAA, software 03.53.45, and webOS 6.5.3-47. The G1 report used SlopBro v0.0.5, which GitHub still marks as Latest. v0.1.0 is a pre-release from 27 Sep 2026, commit 21023d56, message “add workaround for LG’s patch attempt.” That difference was the reason to try v0.1.0 here, not a promise the G1 would follow.

07 OmarchyTV

com.omarchytv.home 2.13.1 was already installed under the developer app path. The in-app banner still says 2.13.0-beta. Number 8 on the remote was already a quick-access slot for it.

On a rooted set the boot behavior is a setting, not a separate machine. Workspace 5, All OmarchyTV settings:

  • Open when the TV starts writes an empty flag at /var/lib/omarchytv/boot and a Homebrew hook at /var/lib/webosbrew/init.d/omarchytv. That hook was present after the switch was turned on.
  • Home button opens OmarchyTV is a second flag. Home from inside OmarchyTV still reaches LG Home.
  • Keep loaded in the background adds the app id to KeepAlive in /home/root/memorymanager-conf.json and restarts memchute.

The third switch showed “rooted TV only” and, on click, asked for root and Homebrew Channel. Homebrew exec was already working: the boot flag and the hook existed. The keep-loaded probe is one shell command whose last step reads the override file. That file does not exist until the switch has been on once, so cat exits 1. The app treats a failed Homebrew command as “not rooted.”

/usr/sbin/memchute does contain the override path, and /etc/palm/memorymanager-conf.json was readable. Its KeepAlive list was com.webos.app.livehbbtv, com.webos.app.livedmost, com.webos.app.liveibb. The override was written as a copy of that file plus com.omarchytv.home, and memchute was restarted. The probe command inside the app was changed so a missing override is not a failed command. After OmarchyTV is opened again, the switch should read on.
